# Migration from UV to Poetry

This document outlines the migration from `uv` to Poetry for the BiblioQuiz project.

## Changes Made

### 1. Package Manager
- **Before**: UV for dependency management and virtual environments
- **After**: Poetry for dependency management and virtual environments

### 2. Configuration Files
- **Updated**: All `pyproject.toml` files converted from PEP 621 format to Poetry format
- **Added**: `poetry.lock` files for each service
- **Removed**: `uv.lock` files

### 3. Docker Integration
- **Updated**: All Dockerfiles now use `requirements.txt` generated by Poetry
- **Simplified**: No longer need to install UV in containers
- **Improved**: Better layer caching with requirements.txt approach

### 4. VS Code Integration
- **Added**: VS Code workspace settings for better Python path resolution
- **Improved**: Poetry virtual environments are automatically detected by VS Code

## Getting Started

### 1. Install Dependencies

Run the setup script to install all dependencies:

```bash
./poetry-vscode-setup.sh
```

Or manually for each service:

```bash
# For each service directory
cd application/loader
poetry install

cd ../orchestrator  
poetry install

cd ../historian
poetry install

cd ../librarian
poetry install

cd ../../share
poetry install
```

### 2. VS Code Setup

1. Open Command Palette (`Ctrl+Shift+P`)
2. Select "Python: Select Interpreter"
3. Choose the Poetry virtual environment for the service you're working on

Poetry virtual environments are typically located at:
- `~/.cache/pypoetry/virtualenvs/`

### 3. Development Workflow

```bash
# Work on a specific service
cd application/loader
poetry shell  # Activate virtual environment
poetry add new-package  # Add dependencies
poetry install  # Install dependencies

# Export for Docker
poetry export --format=requirements.txt --output=requirements.txt --without-hashes

# Run tests
poetry run pytest

# Run the service
poetry run python source/main.py
```

### 4. Docker Deployment

The Docker Compose setup remains the same. Each service now:

1. Uses `requirements.txt` generated by Poetry
2. Installs dependencies with `pip install -r requirements.txt`
3. No longer requires UV installation in containers

```bash
# Build and run services
docker compose up --build
```

## Benefits of the Migration

1. **Better VS Code Integration**: Poetry virtual environments are automatically detected
2. **Simplified Docker Builds**: No need to install UV in containers
3. **Mature Tooling**: Poetry is well-established with extensive documentation
4. **Better Dependency Resolution**: Poetry has robust dependency resolution
5. **Conventional Python Tooling**: Poetry is widely used in the Python ecosystem

## Service Structure

Each service now has:
- `pyproject.toml` - Poetry configuration and dependencies
- `poetry.lock` - Locked dependency versions
- `requirements.txt` - Generated for Docker builds (exported from Poetry)
- `Dockerfile` - Updated to use requirements.txt

## Working with Multiple Services

Since this is a monorepo with multiple services, you'll need to:

1. **Switch virtual environments** when working on different services
2. **Use VS Code's Python interpreter selector** to choose the right environment
3. **Run Poetry commands from the service directory** you're working on

## Troubleshooting

### Poetry Not Found
Make sure Poetry is in your PATH:
```bash
export PATH="/home/vscode/.local/bin:$PATH"
```

### VS Code Not Detecting Virtual Environment
1. Restart VS Code
2. Use Command Palette > "Python: Select Interpreter"
3. Choose the Poetry virtual environment manually

### Dependencies Not Installing
Make sure you're in the correct service directory and run:
```bash
poetry install --verbose
```
